# Typed disclosure contracts and offline scoring

Date: 2026-11-01. Current schema: `typed-disclosure-v3`. The initial offline
preparation was followed by [two real development passes](typed-development-pilot.md).
No held-out evaluation was performed. The 23 development references remain AI drafts.

## What changed

`repurchase_evaluation.py` defines public output fields, unit/date normalization,
response validation and per-question scoring. Dates, original scheme IDs,
amounts, shares, correction scope, prior execution and shareholder gates are
separate fields. It does not coerce every question into the former three stages.
Initial approval, amendment, termination and disposal remain distinct concepts.

Stable enum choices are publicly supplied for correction/event dimensions to
avoid evaluating arbitrary free-form event names. All methods must receive the
same choices. Source approval attribution is an explicit source-ID/date mapping.
Required schema fields are part of the question, not hidden scoring demands.

Money and shares accept exact, explicitly equivalent unit expressions. For
example, 123.45 ten-thousand shares equals 1,234,500 shares. Currency cannot be
used as shares; fractional shares are rejected. Percentage points are not silently
converted from ratios. Numeric booleans are rejected. When asked to preserve the
original erroneous unit wording, the scorer does not repair that wording into
the corrected fact and then reward it as an exact quote.

## Public input and answerability

Prepared prompts expose company, question, cutoff, requested field types and
eligible original documents. They omit reference values, proof spans, split,
reference tiers, task-family labels and the reference scheme ID. A scheme date
explicitly requested in the query remains a legitimate query constraint.
Document bodies are untrusted evidence, never executable instructions.

The model must derive the original scheme identifier from evidence using the
public `CODE_BOARD_YYYY-MM-DD` convention. For comparisons, the later scheme is
the common target while both dates are mapped in the answer; employee plans do
not replace the underlying repurchase scheme.

For future insufficient-evidence questions, declare public `requested_fields`
independently of the empty/insufficient reference. V2 rejects empty public field
schemas so answerability cannot leak through an empty output contract. The
answerable and insufficient versions with the same public inputs have identical
prompts in the regression check. Existing 23 drafts do not establish performance
on naturally insufficient-evidence questions.

## Score interpretation

- Declared field correctness uses exact normalized values; a source/date mapping
  is one field and requires the whole mapping to match.
- Exact answer correctness additionally requires the expected original scheme,
  a valid response shape and eligible supplied citations. Missing or extra answer
  fields do not pass exact scoring. All 23 drafts contain 69 declared fields.
- Every question remains in the denominator. Missing saved predictions are
  incorrect/unanswered; failures must be retained with their question ID rather
  than dropped. Preserve raw malformed responses in separate run records.
- Report answer coverage, task/company breakdowns and company-macro accuracy.
- `reference_designated_source_coverage` only checks inclusion of reference source
  IDs. It is not a semantic entailment score or a list of all valid alternatives.
  The scorer explicitly reports semantic entailment as not automatically judged.

Typed normalization does not fix bad references or semantic extraction errors.
No accuracy improvement on the older 40-item extraction task is implied; this is
a different task contract. Update reference versions and rescore all methods if
human review changes facts. Do not regenerate answers to hide reference mistakes.

## Offline validation

The 23 reference round-trips and 105 deliberately corrupted synthetic responses
check scoring behavior only. Their responses were constructed from reference
drafts, not generated by a model. The negative checks cover wrong schemes,
future sources, invented sources, changed facts and ten-thousand-fold share
errors. **Do not report these checks as 23/23 model accuracy or memory gains.**

The initial offline version had 22 focused cases and 152 root tests. Subsequent
pilot/admission checks bring the current root suite to 162 passing tests; see
the pilot log for the observed market-test flake. Test count is not a financial
sample count. The memory module's earlier 99-test result remains historical.

Versioned output lives under the ignored module experiment directory:

- `typed-development-contract-20261101`: initial v1 preparation snapshot.
- `typed-development-contract-v2-20261101`: initial v2 prompts, synthetic checks,
  input hashes, summary and frozen scoring source.
- `typed-development-contract-v3-20261101`: clarified current public contract used
  in the second real development pass; prior versions remain historical snapshots.

Question/source drafts remain in `development-identity-audit-v3-20261101`.
Initially only prompts were prepared. There are now 46 real development calls
across the two documented passes; formally reviewed references remain zero.

## Commands

```powershell
python scripts/prepare_typed_development.py --audit modules/l0l4-memory/data/experiments/development-identity-audit-v3-20261101 --out workspace/new-typed-preparation
python scripts/score_typed_development.py --audit modules/l0l4-memory/data/experiments/development-identity-audit-v3-20261101 --predictions path/to/responses.jsonl --out workspace/new-typed-scores
python -m pytest -q tests/test_repurchase_evaluation.py
```

The scoring input is one saved response per line with `question_id`, `status`,
`target_scheme`, `answer`, `evidence_ids` and optional `missing_reason`. Unknown
question IDs and duplicate predictions fail rather than silently overwriting.
Failed calls can be represented with the question ID and `status: failed`; they
remain invalid/incorrect. Neither command calls the model. The next empirical
step is an explicitly recorded development pilot after checking this contract;
reserved inference waits for separate source/reference qualification and freeze.
